## Review of load-bearing boundaries

- Bounded state: Local input and each history entry are capped at 64 KiB; history/scrollback are capped at 2,000; `cat`/`edit` at 5 MiB; SSH pending output at 8 MiB with 64 KiB UI batches. The Local bounds were added through observed RED → GREEN regression tests.
- Backpressure: the NIO child channel requests the next read only after the MainActor delivery acknowledgement; cumulative overflow fails closed. Existing application-hosted SSH tests cover batching, stale acknowledgements, overflow, and close cleanup, but are not executable without full Xcode.
- Cancellation/generation: switching/replacing/disconnecting advances reducer generations; stale connection callbacks and stale Local outputs are rejected; manual disconnect/backgrounding cancels retry tasks. Live suspension/reconnect remains OPEN.
- Secrets: host JSON/bookmark defaults contain no password/private-key field. Credentials and fingerprints remain separate Keychain items. Runtime password `String`/`Data` lifetime cannot be proven zeroized by Swift and is not claimed as such.
- Security scope: the folder store maintains one external root, stops before replacement/background fallback, restores the previous scope only on a failed replacement when possible, and balances failure-path stops. Actual Document Picker/File Provider behavior remains OPEN.
