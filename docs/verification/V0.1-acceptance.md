## Review of load-bearing boundaries

- Bounded state: Local input/batch/history entries are capped at 16 KiB, one reducer call at 128 aggregate events, command history at 200 entries/128 KiB total, the Local operation queue at 16 running/queued operations plus 64 KiB declared cost, SwiftTerm scrollback at 2,000 lines, `cat`/editor reads at 5 MiB with 64 KiB chunks and one overflow-probe byte, and SSH pending output at 8 MiB with 64 KiB UI batches. Split-scalar, exact event boundary, multiline paste, blocked-queue rejection/drain/resume, navigation, total-budget, and the Core growing-file read regression execute in the Core runner. The editor wiring regression first failed on the missing bounded-reader seam and now type-checks through the exact-pinned app probe, but remains unexecuted without full Xcode.
- Backpressure: the NIO child channel requests the next read only after the MainActor delivery acknowledgement; cumulative overflow fails closed. Existing application-hosted SSH tests cover batching, stale acknowledgements, overflow, and close cleanup, but are not executable without full Xcode.
- Cancellation/generation: switching/replacing/disconnecting advances reducer generations; stale connection callbacks and stale Local outputs are rejected; manual disconnect/backgrounding cancels retry tasks. Live suspension/reconnect remains OPEN.
- Secrets: the Core runner serializes a representative `SSHHost` and requires exactly the seven allowed metadata keys; a static literal scan is supplemental, not an absolute security proof. Credentials and fingerprints remain separate Keychain items. Runtime password `String`/`Data` lifetime cannot be proven zeroized by Swift and is not claimed as such.
- Deletion: `rm` obtains one exact-target/root-relative/stable-identity prepared value. Core checks execute request/confirm/cancel/non-empty/stale, same-path replacement, target symlink, intermediate-directory symlink-to-same-object, injected request-time A-to-symlink-B replacement, malicious prepared display/logical mismatch, and confirmation identity-mismatch rejection. Coordinated preparation and confirmation/removal each stay within their own single callback; injected app-hosted tests require an outside same-inode relocation and in-root rename to expire without deletion and type-check in the exact-pinned probe, but execution and actual File Provider behavior remain OPEN without full Xcode. The documented direct-storage OS race outside cooperative boundaries also remains OPEN.
- Security scope: the folder store maintains one external root, stops before replacement/background fallback, restores the previous scope only when possible, and otherwise marks reauthorization and reconciles both store and terminal to App Documents. The Core runner executes saturation of the dedicated scheduler with many normal and safety intents, proving a three-transition retention bound and running-then-safety-then-latest-normal order. The injected app-hosted dual-failure and background-safety wiring regressions are written but remain OPEN; actual Document Picker/File Provider behavior remains OPEN.
- Privacy manifests: parsed portable checks verify separate app/framework manifests and distinct target resources. The app declares UserDefaults `CA92.1` and FileTimestamp `C617.1` + `3B52.1`; Core declares only both FileTimestamp reasons. Archive privacy report remains OPEN.
